Вибір предметної області. Аналіз, моделювання та розроблення адаптивного web-застосунку.

Актуальність теми

У сучасних умовах стрімкого розвитку веб-додатків питання безпеки та продуктивності серверної частини набуває критичного значення. Зростання кількості користувачів, збільшення обсягів даних та постійні кіберзагрози вимагають від розробників впровадження ефективних механізмів захисту (Helmet, rate limiting, JWT) та оптимізації (кешування, стиснення відповідей, пагінація). Лабораторна робота №5 присвячена вивченню та практичному застосуванню сучасних інструментів Node.js/Express для забезпечення безпеки та підвищення продуктивності REST API.

Мета роботи

Метою лабораторної роботи було забезпечення базової безпеки Node.js-додатків, оптимізація продуктивності REST API, використання кешування для зменшення навантаження на сервер, тестування API за допомогою сучасних інструментів та аналіз продуктивності backend-застосунків.

Завдання роботи

  1. Створити REST API на Node.js та Express.
  2. Реалізувати захист API: Helmet, rate limiting, валідацію даних.
  3. Реалізувати кешування відповідей (node-cache).
  4. Оптимізувати один із маршрутів API (пагінація + стиснення).
  5. Провести тестування API (Postman + Jest + Supertest).
  6. Проаналізувати продуктивність до та після оптимізації.
  7. Додатково реалізувати: JWT-автентифікацію, Swagger документацію та навантажувальне тестування через Artillery.

Об’єкт роботи

Процес розробки та оптимізації серверного застосунку на базі Node.js та Express.js з акцентом на безпеку та продуктивність. Об’єктом роботи є REST API FilmHub — адаптивний веб-застосунок для управління даними про фільми, що включає автентифікацію, кешування, валідацію, стиснення відповідей та моніторинг продуктивності.

Предмет роботи

Сучасні технології та інструменти забезпечення безпеки й продуктивності Node.js-додатків: Helmet для захисту HTTP-заголовків, express-rate-limit для захисту від надмірних запитів, express-validator для валідації даних, node-cache для кешування, compression для стиснення відповідей, JWT для автентифікації, Swagger для документації API та Artillery для навантажувального тестування.

Бізнес-логіка роботи

Бізнес-логіка лабораторної роботи полягає в створенні надійного, захищеного та високопродуктивного backend-застосунку, здатного витримувати реальне навантаження. Впровадження механізмів безпеки (JWT, rate limiting, Helmet) захищає API від поширених атак, кешування та стиснення зменшують навантаження на сервер і прискорюють відповіді для користувачів, а інструменти тестування та моніторингу (Jest, Supertest, Artillery, performance-test) дозволяють виявляти вузькі місця та забезпечувати стабільну роботу застосунку в умовах реальної експлуатації.

Функціональні вимоги

  1. Створити REST API на Node.js та Express з ендпоінтами для управління даними про фільми (/films).
  2. Реалізувати захист API: Helmet для HTTP-заголовків, express-rate-limit для обмеження запитів та express-validator для валідації даних.
  3. Реалізувати кешування відповідей за допомогою node-cache з автоматичною інвалідацією після змін.
  4. Оптимізувати маршрут /films: додати пагінацію та стиснення відповідей за допомогою compression middleware.
  5. Провести тестування API за допомогою Postman, Jest та Supertest.
  6. Реалізувати ендпоінт /performance-test для аналізу продуктивності з і без кешу.
  7. Додатково реалізувати JWT-автентифікацію (/register, /login + захищені маршрути).
  8. Додатково реалізувати інтерактивну документацію API за допомогою Swagger/OpenAPI.
  9. Додатково виконати навантажувальне тестування через Artillery.

Нефункціональні вимоги

  1. Забезпечення базової безпеки застосунку (захист заголовків, обмеження запитів, валідація вхідних даних, JWT-автентифікація).
  2. Підвищення продуктивності за рахунок кешування, пагінації та стиснення відповідей (gzip/br).
  3. Можливість моніторингу продуктивності в реальному часі (час виконання, використання пам’яті).
  4. Автоматизоване тестування та навантажувальне тестування для перевірки стабільності під навантаженням.
  5. Зручна інтерактивна документація API (Swagger UI).
  6. Чітке розділення коду, використання middleware та дотримання принципів REST.
  7. Легкість розгортання та тестування на будь-якому комп’ютері з Node.js.
  8. Стійкість до поширених веб-загроз (rate limiting, валідація, захищені токени).

Скріншоти роботи

Скріншоти роботи

Рис. 1. Запуск сервера та робота основного ендпоінту /films

Сервер успішно запущено на порту 5000. Демонстрація отримання списку фільмів з бази даних.

Рис. 2. Реєстрація та автентифікація користувача (JWT)

Робота ендпоінтів /register та /login. Отримання JWT-токена після успішного логіну.

Рис. 3. Захищений доступ до /films з використанням JWT-токена

Успішний запит до захищеного маршруту /films після додавання заголовка Authorization: Bearer ...

Рис. 4. Створення нового фільму (POST /films) з валідацією

Успішне додавання фільму через захищений ендпоінт з валідацією даних.

Рис. 5. Аналіз продуктивності (/performance-test)

Порівняння часу виконання запитів з кешем і без кешу. Видно значне прискорення при використанні кешу.

Рис. 5. Інтерактивна документація API (Swagger UI)

Головна сторінка Swagger-документації з усіма ендпоінтами та можливістю авторизації.

Рис. 7. Тестування захищених ендпоінтів через Swagger

Виконання запиту до /films після авторизації безпосередньо в Swagger UI.

Рис. 9. Навантажувальне тестування через Artillery

Результати Artillery-тесту: статистика запитів, час відповіді та демонстрація роботи rate limiting.

Висновок

В ході виконання лабораторної роботи №5 було успішно реалізовано комплекс заходів щодо забезпечення безпеки та підвищення продуктивності серверного застосунку на базі Node.js та Express.js. Було впроваджено ключові механізми захисту (Helmet, rate limiting, валідація даних, JWT-автентифікація), оптимізації (кешування з node-cache, стиснення відповідей, пагінація) та тестування API.

Додатково реалізовано сучасні інструменти: інтерактивну документацію API за допомогою Swagger та навантажувальне тестування за допомогою Artillery. Проведено порівняльний аналіз продуктивності, який чітко продемонстрував значне прискорення роботи застосунку завдяки кешуванню.

Отримані знання та практичні навички дозволяють створювати надійні, захищені та високопродуктивні backend-системи, готові до використання в реальних проєктах. Розроблений FilmHub API може бути легко розширений та інтегрований у повноцінний веб-застосунок.

Всі поставлені завдання лабораторної роботи, включаючи додаткові (JWT, Swagger, Artillery), виконано успішно.
