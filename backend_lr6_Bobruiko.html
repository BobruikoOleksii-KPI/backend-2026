Актуальність теми

У сучасній розробці backend-додатків чітка та актуальна документація API є критичним фактором успішної командної роботи, інтеграції frontend- та mobile-клієнтів, а також швидкого тестування й підтримки проєкту. Swagger (OpenAPI) став промисловим стандартом для автоматичної генерації інтерактивної документації. Крім того, вміння розгортати Node.js-застосунок на хмарному сервісі є обов’язковою навичкою для сучасного backend-розробника. Лабораторна робота №6 є підсумковою і поєднує документування REST API, роботу з MySQL та деплой реального проєкту FilmHub.

Мета роботи

Метою лабораторної роботи є освоєння принципів документування REST API за допомогою Swagger/OpenAPI, інтеграція Swagger UI у Node.js + Express застосунок, створення повноцінної документації всіх endpoint-ів, а також демонстрація підсумкового проєкту — REST API з MySQL.

Завдання роботи

  1. Створити REST API на Node.js + Express (використовуючи код з попередніх лабораторних робіт).
  2. Підключити MySQL та реалізувати повноцінні CRUD-операції.
  3. Інтегрувати Swagger UI у проєкт.
  4. Задокументувати всі наявні endpoint-и за допомогою JSDoc-коментарів (@swagger).
  5. Виконати тестування API безпосередньо через Swagger UI.
  6. Продемонструвати підсумковий проєкт: REST API з MySQL та повною Swagger-документацією.

Об’єкт роботи

Процес розробки, документування та демонстрації повноцінного REST API на базі Node.js + Express з підключенням до бази даних MySQL. Об’єктом роботи є підсумковий проєкт FilmHub — серверна частина веб-застосунку для управління даними про фільми та користувачів з повноцінною автентифікацією, CRUD-операціями та інтерактивною документацією.

Предмет роботи

Інструменти та технології для документування REST API: бібліотеки swagger-jsdoc та swagger-ui-express, специфікація OpenAPI 3.0, JSDoc-коментарі (@swagger), інтеграція Swagger UI у Express-застосунок, а також тестування API безпосередньо через веб-інтерфейс Swagger UI.

Бізнес-логіка роботи

Бізнес-логіка лабораторної роботи полягає у створенні професійного, добре документованого та легко підтримуваого backend-застосунку. Якісна документація API значно прискорює розробку frontend- та mobile-клієнтів, полегшує командну роботу, спрощує інтеграцію з іншими сервісами та дозволяє швидко тестувати ендпоінти без використання Postman. Підсумковий проєкт FilmHub з MySQL та Swagger демонструє готовність до реального використання в production-середовищі.

Функціональні вимоги

  1. Створити повноцінний REST API на Node.js + Express з підтримкою JSON.
  2. Підключити базу даних MySQL та реалізувати CRUD-операції над сутностями (користувачі, пости/фільми).
  3. Інтегрувати Swagger UI у проєкт за допомогою swagger-jsdoc та swagger-ui-express.
  4. Задокументувати всі наявні endpoint-и за допомогою JSDoc-коментарів (@swagger).
  5. Реалізувати автентифікацію та захищені маршрути (JWT + middleware).
  6. Виконати повне тестування API безпосередньо через інтерактивний інтерфейс Swagger UI.
  7. Продемонструвати підсумковий проєкт — FilmHub REST API з MySQL та повною Swagger-документацією.

Нефункціональні вимоги

  1. Повна інтерактивна документація всіх endpoint-ів у форматі OpenAPI 3.0.
  2. Підтримка Bearer JWT авторизації в Swagger UI (кнопка Authorize).
  3. Чітке розділення коду, використання middleware та дотримання принципів REST.
  4. Можливість тестування всіх маршрутів безпосередньо в браузері без Postman.
  5. Коректна обробка помилок та повернення зрозумілих повідомлень.
  6. Сумісність з попередніми лабораторними роботами (автентифікація, Sequelize, CRUD).
  7. Легкість розгортання та запуску проєкту на будь-якому комп’ютері.

Скріншоти роботи

Рис. 1. Запуск сервера та головна сторінка Swagger UI

Сервер FilmHub запущено на порту 3000. Відкрито інтерактивну документацію API за адресою /api-docs.

Рис. 2. Авторизація в Swagger UI (Bearer JWT)

Натискання кнопки Authorize та введення JWT-токена для доступу до захищених маршрутів.

Рис. 3. Реєстрація користувача через Swagger UI

Успішне виконання POST /register безпосередньо в Swagger.

Рис. 4. Авторизація користувача (POST /login)

Отримання accessToken та refreshToken після логіну через Swagger.

Рис. 5. Перегляд профілю (GET /profile — захищений маршрут)

Успішний доступ до захищеного ендпоінту після авторизації.

Рис. 6. Отримання всіх постів (GET /posts)

Перегляд списку постів з бази даних MySQL через Swagger UI.

Рис. 7. Створення нового поста (POST /posts)

Успішне створення поста через Swagger з автоматичним збереженням у MySQL.

Рис. 8. Повний CRUD постів (GET /posts/{id}, PUT, DELETE)

Демонстрація читання, оновлення та видалення поста за ID.

Висновок

В ході виконання лабораторної роботи №6 було успішно завершено підсумковий проєкт курсу. На базі раніше розробленого REST API FilmHub з підключенням до MySQL було інтегровано сучасну систему документування — Swagger/OpenAPI. Всі ключові ендпоінти (автентифікація, CRUD-операції з постами, захищені маршрути) були повністю задокументовані за допомогою JSDoc-коментарів та стали доступними через інтерактивний інтерфейс Swagger UI.

Особливо варто відзначити зручність тестування API безпосередньо в браузері без використання Postman, а також коректну роботу Bearer JWT авторизації в Swagger. Отримані знання та навички дозволяють створювати професійні, добре документовані та легко підтримувані backend-системи, готові до використання в реальних командних проєктах.

Лабораторна робота №6 продемонструвала повний цикл backend-розробки: від створення REST API з базою даних MySQL до сучасного документування та тестування. Всі поставлені завдання виконано успішно.
